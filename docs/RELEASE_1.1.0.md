# 1.1.0 功能與升級說明

## 新功能

- 管理員與員工均可在「修改密碼」驗證原密碼後設定新密碼，所有舊登入立即失效。
- 管理員可在操作員管理重設員工密碼；不能以此端點重設其他管理員密碼。管理員修改自己的密碼需驗證原密碼。
- 登入頁新增「一般使用者查詢」。使用自己的 QR 憑證登入，只能查本人餘額與交易，不能發點、扣點、列出其他會員或讀取操作員資料。查詢登入十分鐘到期，重發 QR 或停用會員立即使原查詢登入失效。共用設備使用完畢請登出。
- 點數餘額與管理員目標餘額可為負數；發點及扣點的單次額度仍須正整數。整數餘額與單筆增減均限制在 ±9,007,199,254,740,991 範圍。兩人可同時扣成負數，例如 500 連續扣兩筆 400，最後 -300，兩筆皆留帳。
- 操作員與一般查詢頁均可開啟相機掃 QR，也可辨識 QR 圖片。相機掃碼只查詢並呈現會員，扣點仍需再確認。
- 交易紀錄與 CSV 加入會員名稱、會員編號及操作員帳號名稱。介面角色、狀態、交易種類、CSV 欄位與安裝精靈改用繁體中文，程式識別碼與檔名保留。

一般使用者持有 QR 即可查本人資料，靜態 QR 可被複製，請妥善保管。此版沒有新增會員帳密／自助註冊，也沒有將整套服務公開至 Internet。

## 相機與 HTTPS

瀏覽器在 http://localhost 可使用相機。其他設備透過一般 http://區域網路IP 連線時，瀏覽器會禁止即時相機；介面會說明原因並保留圖片與 USB 掃描器輸入。

主機可直接以 TLS 提供 HTTPS。在受保護的資料目錄 config.json 加入由管理員配置的憑證及金鑰，例如：

```json
{
  "port": 8080,
  "tls_certfile": "C:\\ProgramData\\QRPointSystem\\tls\\server.crt",
  "tls_keyfile": "C:\\ProgramData\\QRPointSystem\\tls\\server.key"
}
```

兩個檔案必須同時提供，憑證 SAN 必須包含實際使用的主機 DNS 名稱或 IP，並讓各設備信任簽發 CA。這需要主機／裝置管理員依環境配置，程式不會自動安裝信任根憑證或略過瀏覽器憑證警告。設定後停止並重新啟動服務，各設備改以 https://主機IP:8080 連線，允許相機權限。啟用 TLS 時登入 Cookie 自動使用 Secure。亦可沿用組織的 HTTPS 反向代理並設定 secure_cookie=true，封鎖外部直接連線 HTTP 後端。

圖片辨識在設備本機處理，不會上傳圖片或呼叫雲端服務。相機辨識使用隨程式打包的 ZXing 函式庫，不依賴 CDN。

## 升級與資料保留

1. 暫停操作，備份原 DB、secret.key、config.json 及舊程式版本。
2. 正常停止服務，執行 1.1.0 Setup.exe，選原資料目錄及 Windows 執行帳號。
3. 啟動後自動先備份，再以資料庫交易從 Alembic 0001 升級為 0002；保留會員、操作員、QR、餘額、流水帳及冪等鍵，重建允許負數的約束。
4. 升級成功後核對歷史紀錄與 QR，各瀏覽器 Ctrl+F5。

若升級失敗，程式停止啟動且資料庫結構與資料回滾。新版本含負數 schema，不能直接使用舊版 EXE 開啟；要回退，必須使用升級前備份與舊程式。一般 restore 仍要求備份 schema 與目前版本一致，不能將 0001 備份直接還原到已升級的 0002 主庫。

## 驗證

新增密碼權限、登入撤銷、會員查詢隔離、查詢逾時／限速、QR 撤銷、負餘額併發、上下界及舊資料庫升級／故障回滾測試。瀏覽器驗證管理員改密碼與重新登入、員工重設、負點、姓名與中文、會員查詢／登出、真實 QR 圖片解碼及模擬相機影片串流解碼與鏡頭釋放。實體手機／筆電鏡頭及現場信任鏈需另行驗證。
